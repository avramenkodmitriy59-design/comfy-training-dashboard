# Дашборд навчання COMFY

Веб-дашборд залученості й успішності проходження навчання по мережі: фільтри по
регіону/магазину/посаді/сегменту, живі графіки, окремий розріз для атестації,
історія по періодах.

## Стек

- Бекенд: Python + Flask + SQLite (`app.py`, `db.py`, `aggregate.py`). Дані
  зберігаються в `data/dashboard.db`, спільні для всієї команди — не в браузері.
- Фронтенд: одна сторінка на vanilla JS (`static/js/app.js`), без збірки.
  Excel (.xls) парситься прямо в браузері бібліотекою SheetJS, графіки — Chart.js.
- Доступ — по спільному паролю (без реєстрації користувачів).

Пароль генерується автоматично при першому запуску і зберігається в
`data/secrets.json` (поле `password`). Подивитись його:

```

```

## Дані

- В базі вже завантажені реальні звіти з папки `Звіти/` за 1–3 квартал 2026
  (загальний звіт — 2 і 3 квартал; атестація по всіх 5 посадах — 1, 2, 3 квартал).
- Класифікація посад (Фронт/Бек, Перша лінія) у `data/dashboard.db`
  (таблиця `positions_config`) — редагується прямо в інтерфейсі, кнопка
  «Класифікація посад».
- **Нормалізація назв посад:** LMS вивантажує довгі бюрократичні назви
  замість тих, якими користуються в компанії — вони автоматично
  приводяться до коротких назв при завантаженні файлу (`aggregate.POSITION_ALIASES`),
  однаково у звіті "всі посади" й в атестаційних файлах:
  - «Фахівець з прийому і видачі товару в магазині» → **Комірник**
  - «Фахівець з викладки» → **Вантажник**
  - «Заступник керуючого магазином з ІТ-сервісів» → **ІТ лідер**
  - «Заступник керуючого магазином з торгових процесів» → **Заступник з ТП**
  - «Менеджер в роздрібній торгівлі побутовими товарами та їх ремонті» → **Сервіс менеджер**
  - «В/о керуючого магазином» прирівнюється до **Керуючий магазином** (одна й та сама посада)
  Якщо в LMS зустрінеться назва, якої немає в цьому списку, вона просто
  зберігається як є і позначається «потребує класифікації» — виправляється
  вручну в «Класифікація посад».
- **Період:** у дашборді є фільтр «Період» — можна переглянути будь-який
  завантажений квартал, не тільки останній. Усі фільтри (регіон/магазин/
  посада/сегмент/перша лінія) і список співробітників працюють однаково
  для кожного періоду — детальні рядки по співробітниках зберігаються
  назавжди для всіх періодів, а не тільки для найсвіжішого.
- **Важливо:** завантажуйте нові періоди в хронологічному порядку (спочатку
  старіший період, потім новіший) — графік динаміки й вибір «поточного»
  періоду будуються за порядком завантаження, а не за текстом мітки періоду.

### Проєкти

Вкладка «Проєкти» об'єднує два різні за суттю типи даних під одним чипом-перемикачем:

- **SEB академія** (і будь-які майбутні курси того самого типу) — звіт по
  курсу з тестами/ДЗ на людину. Один проєкт = один період за раз (label
  вводиться вручну), фільтр «Посада» — реальна посада співробітника.
- **AEP (Apple Excellence Program)** — облік тренінг-сесій (`Звіти/AEP/`),
  геть інша модель: ціль — 100 учасників на навчальну тему за квартал
  (сумарно по всіх слотах; до Q3 2026 ціль була 60 — див. `aep_goal_for_quarter`
  у `aggregate.py`). Один файл «Графік тренінгів Apple» містить одразу
  кілька років — при кожному завантаженні дашборд сам визначає квартал
  кожної сесії з дати і **замінює** дані саме цього кварталу (не додає
  новий період і не плутає з іншими). Щокварталу просто вивантажуйте той
  самий файл повторно — старі квартали лишаються, новий/виправлений
  оновлюється автоматично.
  «Рівень» у таблиці тем (Apple чемпіони / Непрограмні учасники) визначається
  з колонки «Цільова аудиторія» — це властивість САМОЇ СЕСІЇ («на кого вона
  розрахована»), не конкретних людей, і «Резервісти» там ніколи не з'являться
  окремо, бо в цьому файлі це просто немає такої мітки аудиторії.

  **Реальна відвідуваність по людях** — окрема підсистема, збудована на двох
  додаткових джерелах (не пов'язаних із таблицею тем вище):
  - вкладка `Apple_Certified_-_Attendance` у тому самому файлі «Графік
    тренінгів Apple» — рядок на кожного учасника кожної сесії (ПІБ, магазин,
    статус CHECKED_IN/REGISTERED/NO_SHOW/CANCELLED/INVITED). Парситься й
    зберігається автоматично при кожному завантаженні основного AEP-файлу
    (`aep_attendance` у БД, оновлюється по кварталах так само, як і теми).
  - окремий файл **«Apple Excellence Program.xlsx»** (вкладка «Резервісти та
    чемпіони») — поточний список хто саме зараз чемпіон/резервіст по
    магазинах. Завантажується окремим полем у тій самій модалці
    «Завантажити дані» → «AEP — ростер чемпіонів і резервістів». Це знімок
    поточного стану, не період: кожне завантаження **повністю замінює**
    попередній ростер (`aep_roster` у БД), а не накопичує історію.

  Людину з відвідуваності зіставляють з ростером по нормалізованому ПІБ
  (`aggregate.normalize_person_name` — без урахування регістру/порядку
  імені/прізвища). Зіставлення orієнтовне: на реальних даних співпадає
  ~85 зі 87 записів ростера, решта — або нові учасники, яких ще нема в
  логах відвідуваності, або розбіжності в написанні імені між файлами.
  Люди поза ростером потрапляють у "Інші учасники".

  Це дає три блоки на сторінці AEP (ховаються самі, якщо даних нема —
  наприклад для кварталів, завантажених до появи цієї фічі):
  - «Відвідуваність по рівнях» — % CHECKED_IN серед Apple чемпіон/Резервіст/
    Інші учасники за обраний квартал.
  - «Відвідуваність по тренінгу» — обрати конкретну сесію (тема + дата) і
    побачити список усіх учасників зі статусом.
  - «Систематично не відвідують» — рейтинг людей з найгіршим % CHECKED_IN
    серед тих, у кого мінімум 2 записи цього кварталу (щоб не показувати
    шум з одиничних збігів).

Обидва типи проєктів (SEB/AEP) всередині використовують ту саму таблицю
`details` (поля region/store/position/name просто означають різне — для AEP
це рівень/тип заходу/тема/відповідальний, не регіон/магазин/посада/ПІБ).
`aep_attendance`/`aep_roster` — окремі таблиці, не частина цієї схеми.

## Розгортання в інтернеті (щоб команда мала доступ не лише з цього комп'ютера)

Це звичайний Flask-застосунок (продакшн-сервер — `gunicorn`, вже в
`requirements.txt`), тому підходить будь-який хостинг з підтримкою Python.
Репозиторій вже містить `render.yaml` — Render підхопить з нього build/start
команди й диск автоматично ("New Blueprint" замість "New Web Service").

1. Створіть git-репозиторій з цієї папки (без `data/`, `.venv/` — див.
   `.gitignore`) і запуште на GitHub.
2. На Render: "New" → "Blueprint" → підключити репозиторій — `render.yaml`
   налаштує все саме. Якщо хостите деінде (Railway тощо) без підтримки
   Blueprint — налаштуйте вручну:
   - Build command: `pip install -r requirements.txt`
   - Start command: `gunicorn -w 2 -b 0.0.0.0:$PORT app:app`
   - Змінна середовища `DASHBOARD_PASSWORD` — щоб самим задати пароль
     (інакше згенерується новий при першому старті і його треба буде
     подивитись у логах).
3. **Диск:** SQLite-файл (`data/dashboard.db`) повинен лежати на persistent
   диску, інакше дані зникнуть при кожному передеплої. `render.yaml` вже
   декларує такий диск (платний тариф — persistent disk на безкоштовному
   тарифі Render недоступний), або перейдіть на Postgres-адон, якщо
   потрібен безкоштовний варіант з надійним зберіганням.
4. Розкажіть команді URL і пароль.

Якщо потрібна допомога з конкретним хостингом (Render/Railway/власний
сервер) — звертайтесь, підкажу покроково під ваш варіант.

## Структура проєкту

```
app.py            Flask-бекенд, усі /api/* маршрути
db.py             Схема SQLite і дефолтна класифікація посад
aggregate.py      Логіка агрегації (та сама, що описана у ТЗ) + визначення
                   атестаційної посади з колонки "Посада"
static/
  index.html       розмітка SPA
  css/style.css    стилі, фірмові кольори й шрифти COMFY
  js/app.js        уся логіка інтерфейсу, парсинг Excel, графіки
  js/vendor/       SheetJS, Chart.js (локальні копії, без залежності від CDN —
                   xlsx.full.min.js тут ВРУЧНУ пропатчений: додано обробку
                   ODS-клітинок з office:value-type="error" (формула на кшталт
                   ділення на 0), інакше вся книга Apple падає при парсингу.
                   Якщо колись оновлюватимете цю бібліотеку — перенесіть патч,
                   інакше AEP-файли перестануть завантажуватись)
  fonts/           Comfy Semi-Bold (заголовки), PT Root UI (основний текст)
  assets/          логотипи COMFY
Звіти/             вихідні Excel/ODS-звіти (не потрібні для роботи застосунку)
```
